## 2025-04-14 - Cache detectPackageManager Result as a Promise
**Learning:** When optimizing async checks like package manager detection (`detectPackageManager`) using module-level caching, caching the `Promise` itself rather than the resolved value prevents redundant system calls from concurrent executions. Avoid `Promise.any` for concurrent checks, as it introduces a non-deterministic race condition that breaks the intended fallback order. Ensure to expose an internal clearing method (like `_internalClearPackageManagerCache`) to prevent state leakage between unit tests.
**Action:** For async initialization or detection routines, cache the in-flight `Promise` so all subsequent callers await the exact same promise. Always include a module-level clear function specifically for test isolation.
