## 2024-05-24 - Command Injection via execSync with stderr redirects
**Vulnerability:** Shell command injection (CWE-78) and potential process deadlocks were identified in `execSync` usages within `recordAudio`, which accepted arbitrary inputs and shell features like `2>/dev/null`.
**Learning:** When executing system commands, prefer `execFileSync` over `execSync` to strictly enforce argument arrays without shell evaluation. However, simply replacing `execSync` with `execFileSync` while migrating shell redirection (like `2>/dev/null` or `2>NUL`) requires appropriately handling the `stdio` option. Neglecting to natively ignore or consume the `stderr` buffer by setting `stdio: ['ignore', 'pipe', 'ignore']` can cause verbose tools like `ffmpeg` to deadlock.
**Prevention:** Always use `execFileSync` or `spawn` instead of `execSync` to pass array arguments safely, avoiding shell metacharacter vulnerabilities. When removing stderr redirects from the shell command, configure the child process `stdio` arrays appropriately to prevent output buffer deadlocks. Also, ensure array arguments on Windows are not manually quoted (e.g. use `audio=Microphone` directly, not `'audio="Microphone"'`), as Node handles the escaping correctly natively.
